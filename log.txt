## Steps
1. **Relocate the scaffold.** Create `agent-screen-starter/invoice-triage/{.claude-plugin,commands}`. Then remove the stray empty `curie-python/invoice-triage/` so there aren't two copies.
2. **Manifest.** Write `invoice-triage/.claude-plugin/plugin.json` with name `invoice-triage`, the description from AGENT.md, and version `0.1.0`.
3. **Command.** Write `invoice-triage/commands/invoices-today.md`:
   - Frontmatter: a description, plus `allowed-tools: mcp__mock-invoices__list_open_invoices` so the command can only use that one read-only tool.
   - Call `list_open_invoices` from the `mock-invoices` MCP server. Don't read `mock_invoices.py`.
   - Convert `balance_cents` to dollars.
   - Bucket the invoices with 2026-10-19 as the reporting date:
     - PAST DUE: due before 10-19.
     - DUE WITHIN 7 DAYS: 10-19 through 10-26 inclusive.
     - MISSING INFORMATION: null `due_date`.
   - Handle any invoice that fits none of the three buckets (for example, due more than 7 days out) by leaving it out of the report, and say so.
   - Sort each bucket by balance, descending.
   - Print a table per bucket with id, customer, balance, due_date, and days overdue. Days overdue is filled in only for past-due invoices and blank otherwise.
   - Close with total past-due exposure and the single top-priority account.
   - State that the command is read-only: no messages sent, no data modified.
4. **Plugin README (small).** Add `invoice-triage/README.md` with how to run it, the bucket definitions, and the assumptions: the fixed reporting date, the 7-day window, and null due dates reported rather than aged. A reviewer will see this on GitHub.
5. **Skipped on purpose.** The `triage.py` script from the AGENT.md optional upgrade. A script run through Bash can't call the MCP tool, so the JSON would have to be passed in, and that weakens the determinism argument. I'll revisit if you want it.
